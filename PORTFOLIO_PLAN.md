# Portfolio Website — Build Plan for Claude Code

> **How to use this file:** Put it in the root of an empty project folder, then tell Claude Code:
> *"Read PORTFOLIO_PLAN.md and build the site phase by phase. Stop after each phase, run the checks listed, and show me the result before continuing."*

---

## 1. Goal

Build a fast, modern personal portfolio for **John Lexter, Software Developer**, using the content from his CV.

- All text content lives in **JSON data files**. Changing content never requires touching components.
- One source of data powers **both** the website and a printable `/cv` page.
- Every image is a **placeholder** that can be swapped by replacing one file or one path in the data.
- The styling is **documented**: design tokens, mixins and component styles live in commented SCSS files.
- The look is a **playful, light-only "game UI" style** (character-select screen): chunky rounded cards, black number pills, outlined section numerals, slanted image frames, and a holographic gradient on hover. The full design spec is in §7. **There is no dark mode.**

## 2. Tech stack and decisions

| Concern | Choice | Notes |
|---|---|---|
| Framework | **Astro 6** (latest stable) | Static output (`output: 'static'`). |
| Language | **TypeScript** (strict) | |
| Interactive UI | **React** via `@astrojs/react` | Used only for islands that need interactivity. |
| Component library | **shadcn/ui** | Follow the *current* official shadcn/ui installation guide for Astro (`ui.shadcn.com/docs/installation/astro`). Do not hardcode older steps from memory. |
| Styling | **SCSS (Sass)** for all custom styles + **Tailwind** only as shadcn's required dependency | See §2.1. |
| Content | **Astro content collections** backed by JSON files, validated with Zod schemas | See §4. |
| Icons | `lucide-react` (ships with shadcn) | |
| Font | **Outfit** via `@fontsource-variable/outfit` | Self-hosted variable font (weights 300–900). |
| Deployment | Cloudflare Pages or Netlify (static) | Phase 7. |

### 2.1 Styling strategy (important)

shadcn/ui components are styled with Tailwind, so Tailwind must be installed for them to work. To keep the codebase readable and documented:

1. **Tailwind is used only inside `src/components/ui/`** (the generated shadcn components). Do not write Tailwind utility classes in our own components.
2. **All our own styling is SCSS**, using `*.module.scss` files next to each component, plus global partials in `src/styles/`.
3. **One set of design tokens.** Colors, radius and fonts are defined once as CSS custom properties in `src/styles/_tokens.scss`. shadcn's theme variables (`--background`, `--foreground`, `--primary`, `--radius`, etc.) are mapped to these same tokens so shadcn components and SCSS components always match.
4. Every SCSS partial starts with a comment block explaining what it contains and how to use it.

### 2.2 React usage rules

- Pages and static sections are `.astro` components (no JS shipped).
- Use React (`.tsx`) only for interactive pieces: mobile nav menu, the player card's Stats/Ability tabs, project filter, count-up numbers, dialogs.
- Hover effects are **pure CSS** (§7.4); never use JS for hover.
- Use the lightest hydration directive that works: prefer `client:visible` or `client:idle`; use `client:load` only for above-the-fold interactivity (e.g. nav).

## 4. Content data

### 4.1 Rules

- Dates are stored as `"YYYY-MM"` strings, or `null` for "Present", and formatted in components.
- Every list item has a stable `id` or `slug`.
- Optional fields are present but set to `null` (or `[]`), so the shape is consistent.
- Image paths point to placeholders in `public/images/`. Swapping an image means replacing the file or changing the path.
- Define every collection in `src/content.config.ts` using Astro's `file()` loader and a Zod schema. Use the import paths shown in the current Astro docs for `defineCollection`, `file` and `z`. The build must fail if data doesn't match the schema.
- `site.json` is a single object; import it directly (or as a one-entry collection).

### 7.3 Shape

- Radius: `999px` pills/buttons · 26–34px cards · 44px contact panel · 14px highlight blocks.
- Cut corners (mixin `cut-corner($size, $corners)`): 40px on the hero photo, 26px top-right on the Base tile.
- Slant (mixin `slant($pct)`): 7% parallelogram for project image frames; 10px slant for DateTags.
- Diamonds: 9–11px squares rotated 45° as bullets and level markers.
- Touch targets ≥ 44px; primary buttons 56px tall.

### 7.4 Interactivity and hover (`_effects.scss`)

Three utility classes, all pure CSS, applied to components through their props (e.g. `<StatPill hover="fill-dark">`):

1. **`.hf` — holo fill** for every *filled* element (black pills, violet buttons, lime/yellow blocks, gray chips, tabs, black cards, the contact panel). On hover the background fades to `--holo`:
   - the element gets `position: relative; isolation: isolate`;
   - a `::before` with `inset: 0; border-radius: inherit; background: var(--holo); background-size: 200% 200%; opacity: 0; z-index: -1; transition: opacity .3s` sits between the element's own background and its content;
   - `:hover::before { opacity: 1; animation: holo-shift 3s linear infinite alternate }` where `holo-shift` moves `background-position` from `0% 50%` to `100% 50%` (the shimmer).
2. **`.hf-dark`** — add together with `.hf` on elements with **white text** (black and violet ones). On hover all text, icons and borders inside switch to `--ink` (`.hf-dark:hover, .hf-dark:hover * { color: var(--ink) }`), divider lines (`.rule`) become `rgba(17,18,20,.35)`, and watermarks (`.wm`) become `rgba(17,18,20,.07)`. This keeps contrast on the light gradient.
3. **`.hr` — holo ring** for every *white* element (nav bar, cards, info tiles, secondary buttons). On hover a 3px gradient outline fades in:
   - `::after { inset: 0; border-radius: inherit; padding: 3px; background: var(--holo); background-size: 200% 200%; mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0); mask-composite: exclude; -webkit-mask-composite: xor; opacity: 0; transition: opacity .3s; pointer-events: none; z-index: 5 }`, with the same shimmer animation on hover.

Also:
- `.lift` (project cards): hover `translateY(-6px) rotate(-.6deg)`, 250ms `cubic-bezier(.2,.8,.2,1)`.
- `.press` (buttons): hover `translateY(-2px)`, 150ms.
- **Focus**: every element with `.hf` or `.hr` shows the same effect on `:focus-visible`, plus a 3px violet focus ring with 3px offset.
